# B05 机构联系：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-lender-contact`
**目标：** 识别平台、贷款方及服务方，查询与事项匹配的官方联系方式和办理入口。
**职责边界：** 只查联系方式不强制建账或收集收入；查询不等于已联系。协商/投诉材料另交 B06/B07。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| purpose | string/enum | 必需 | 还款、入账、协商、投诉或其他联系目的 |
| platform / product / legal_entity | object | 主体识别 | 展示名与合同主体分开；不确定不强匹配 |
| contract_clues | array | 多主体时 | 脱敏合同/账单线索，非必需不收全合同 |
| region | string / null | 渠道有地域差异时 | 当前事项适用地区，不任意推断 |
| directory_result | object / null | 内部目录查询时 | 记录来源、角色、核验日和适用范围 |
| web_evidence | array | 联网补查时 | 官方域名/原文 URL、抓取时点、对应主体 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 理解联系目的与已知主体 | 多主体才补线索，不做无关信息采集 | 待联系主体 |
| S02 | 识别平台/贷款/服务/委托关系 | B05-R01/B05-R02；歧义时 get_user_choice 选择核实路径 | 主体及角色 |
| S03 | 优先查内部核验目录，过期/缺失再联网 | B05-R03/B05-R04；目录不可用不等于无渠道 | 候选渠道 |
| S04 | 核验官方来源和事项适用性 | 冲突/失效按 B05-R05；不采用搜索摘要当已核验原文 | 可用/未核验渠道 |
| S05 | 展示联系方法、要求、时间和来源 | B05-R06；用户要代联系时检查真实工具和对应授权 | institution_contacts |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| entities[] | 机构法定名、角色、与产品关系及待确认点 |
| contacts[] | 渠道、官方链接、事项、服务时间、材料、适用地区 |
| verification | 来源、核验时间、冲突及未确认部分 |
| action_state | 仅查询 / 准备材料 / 有实际执行回执 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "entities": [
    {
      "name": "合成示例机构",
      "role": "lender",
      "verified": false
    }
  ],
  "contacts": [],
  "verification": {
    "status": "unverified",
    "reason": "示例未查询真实渠道"
  },
  "action_state": "lookup_only"
}
```

- 已有：deepseek_search、deepseek_fetch、get_beijing_time、get_user_choice；按需文件工具

点号形式均为拟议逻辑能力别名；后续可实现为普通 Tools 或 MCP，但不得直接在运行时调用未注册名称。未实现能力只产生明确缺口，不通过脚本绕过权限或自行连库。原生 Skill 资源工具与业务查询工具分别由当前配置提供；不能因加载入口就假定所有依赖可用。

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |
