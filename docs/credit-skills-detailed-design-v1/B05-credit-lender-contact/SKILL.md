# 机构联系（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

识别平台、贷款方及服务方，查询与事项匹配的官方联系方式和办理入口。

只查联系方式不强制建账或收集收入；查询不等于已联系。协商/投诉材料另交 B06/B07。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 理解联系目的与已知主体。多主体才补线索，不做无关信息采集；产出：待联系主体。
2. 识别平台/贷款/服务/委托关系。B05-R01/B05-R02；歧义时 get_user_choice 选择核实路径；产出：主体及角色。
3. 优先查内部核验目录，过期/缺失再联网。B05-R03/B05-R04；目录不可用不等于无渠道；产出：候选渠道。
4. 核验官方来源和事项适用性。冲突/失效按 B05-R05；不采用搜索摘要当已核验原文；产出：可用/未核验渠道。
5. 展示联系方法、要求、时间和来源。B05-R06；用户要代联系时检查真实工具和对应授权；产出：institution_contacts。

- 已有：deepseek_search、deepseek_fetch、get_beijing_time、get_user_choice；按需文件工具
- 拟议：institution.directory、contact.verified_query；真实联系另行建设

拟议能力名不是可直接调用的现有工具。只能使用当前运行环境真实提供的工具；缺失时说明影响，不能自行假定存储、计算或外部动作成功。已获得的数据和来源传回主 Agent，由它按用户目标选择后续 Skill。

输出区分已证实、待核实、缺失和实际动作状态。取消、冲突或等待中不把计划当执行完成。字段、证据与完成条件见详细设计第 4 节，按业务规则表和已确认事实解释，不杜撰结果。
