# B08 征信解读：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-report-interpretation`
**目标：** 解读用户私有征信报告，解释账户、还款历史及查询记录，形成带报告日期与原文定位的摘要。
**职责边界：** 不把报告余额当实时应还，不生成未知信用评分或获批概率；用户未要求融资不进入 B09。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| artifact_ref / report_type | reference + string | 必需 | 当前用户有权访问的附件；类型未知先识别 |
| report_date / scope | date + object | 解读必需 | 报告日期、页数与覆盖范围 |
| focus | string / null | 用户指定时 | 只解读关注点或给基础摘要，不无限提取资料 |
| accounts / repayment_history | candidate arrays | 按报告实际存在 | 账户去重、余额、历史代码与报告口径 |
| inquiries / other_sections | candidate arrays | 按实际类型 | 查询原因与次数按已验证定义 |
| source_locations / parse_limits | arrays | 所有抽取 | 页码/位置、缺页/清晰度/截断及无法识别项 |
| confirmation / save_scope | object / null | 形成画像时 | 解读、确认、长期保存分别标识 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 识别报告类型、日期、用户关注点 | B08-R01/B08-R02；未知格式不套已知模板 | 解读范围 |
| S02 | C02 检查解析覆盖、页数与清晰度 | B08-R03；缺页只能局部解读 | 候选字段和局限 |
| S03 | 按适用模板校验账户、统计和代码 | B08-R02/B08-R04；不重复累计同一账户 | 报告摘要候选 |
| S04 | 影响用户任务的歧义通过 C01 核实 | B08-R05；报告原文与用户更正陈述分开 | 已核实/待核实 |
| S05 | 解释原文与报告时点限制 | B08-R04/B08-R06；不作未知审批概率预测 | credit_report_summary |
| S06 | 用户要求保存/匹配时另行衔接 | B08-R07，C03/B09；不因上传自动授权转交 | 后续任务或结束 |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| report_metadata | 类型、日期、页数、覆盖和解析版本 |
| accounts / history / inquiries | 报告实际字段及证据引用 |
| explanations / limitations | 术语、可证事实、缺页和不能推断的结论 |
| profile_candidates | 可供用户核实的候选画像，不自动落库 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 8. 验收场景（设计，尚未运行）

| 场景 | 输入条件 | 期望行为 |

## 9. 规划运行包的完整结构与资源章节

以下为定稿后拟生成的结构，当前只存在本文件第 1 节说明的设计文件。DESIGN.md 与业务审查状态保留在设计区；正式包是否携带已定稿规则摘要，应在打包时确认，不复制未填写表投入运行。

```text
credit-report-interpretation/
├── SKILL.md
├── references/
│   ├── business-rules.md
│   ├── report-layouts.md
│   └── report-terms.md
└── scripts/
    └── check_report_totals.py
```

| 规划资源 | 内容章节 / 输入输出 | 规则依据与边界 |
|---|---|---|
| references/report-layouts.md | 已验证类型/版本 → 页区与字段映射 → 报告日期 → 账户关联/去重 → 统计 → 不支持范围 | B08-R01—B08-R03；待脱敏样例后定稿，不空造版式 |
| references/report-terms.md | 术语/代码 → 官方定义与来源 → 报告适用版本 → 原文解释 → 不能推断的内容 | B08-R04—B08-R06；不含虚构评分或获批概率 |
| scripts/check_report_totals.py | 输入：已验证类型、账户候选、统计定义、原文位置。输出：重复疑点、日期异常、已定义合计差异和缺失字段。 | 不同类型未知先返回不支持；不将报告余额直接变成实时应还 |

脚本执行契约（设计）：以明确传入 JSON 为输入，不读取宿主资料或密钥；输出结构化校验结果，含 checks / errors / missing_fields / rule_version。业务资料不完整是可解释结果，不用通用异常吞掉。格式/运行失败保留实际错误；超时/资源限制遵守已配置执行器。没有按需脚本输入输出能力时，后续接入需先设计适配，不能把本契约当现有原生工具签名。所有输出由工具结果交回主任务，脚本不写正式业务数据库。
