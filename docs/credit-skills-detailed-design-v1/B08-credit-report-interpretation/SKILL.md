# 征信解读（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

解读用户私有征信报告，解释账户、还款历史及查询记录，形成带报告日期与原文定位的摘要。

不把报告余额当实时应还，不生成未知信用评分或获批概率；用户未要求融资不进入 B09。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 识别报告类型、日期、用户关注点。B08-R01/B08-R02；未知格式不套已知模板；产出：解读范围。
2. C02 检查解析覆盖、页数与清晰度。B08-R03；缺页只能局部解读；产出：候选字段和局限。
3. 按适用模板校验账户、统计和代码。B08-R02/B08-R04；不重复累计同一账户；产出：报告摘要候选。
4. 影响用户任务的歧义通过 C01 核实。B08-R05；报告原文与用户更正陈述分开；产出：已核实/待核实。
5. 解释原文与报告时点限制。B08-R04/B08-R06；不作未知审批概率预测；产出：credit_report_summary。
6. 用户要求保存/匹配时另行衔接。B08-R07，C03/B09；不因上传自动授权转交；产出：后续任务或结束。
