# C03 画像与记忆：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-profile-memory`
**目标：** 按当前用户与任务读取相关画像/长期记忆，并整理、确认、纠正或删除明确表达与核验过的信息。
**职责边界：** 账务真值由业务数据管理；不保存模型推测；没有持久化工具不承诺下次记得。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| operation / task_scope | enum + reference | 必需 | read / propose / save / correct / delete；当前任务目的 |
| principal_scope | trusted context | 必需 | 后端注入，模型不可选择其他用户 |
| candidate / existing | objects | 变更时 | 新旧值、类别、来源、有效日期、已确认状态 |
| data_class | enum | 读写必需 | business_fact / profile / memory，决定归属服务 |
| valid_from / expires_at | date / null | 时效信息 | 有效期策略待 C03-R03，不使用虚构永久有效 |
| confirmation_ref | object / null | 必要确认时 | 绑定确切变更与版本，未回复不能写正式事实 |
| write / correction / delete_receipt | object / null | 动作完成 | 实际回执、被替代记录和失败影响 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 明确当前任务与信息用途，校验用户范围 | C03-R01，后端身份；无关画像不检索 | 可处理范围 |
| S02 | 分类业务事实、画像或长期记忆 | C03-R02；账单更新交 B01，避免双写真值 | 目标存储类别 |
| S03 | 按任务检索并检查有效期和冲突 | C03-R03/C03-R04，G02/G03；记忆不能替当前余额 | 相关片段/候选差异 |
| S04 | 必要变更通过 get_user_choice 确认 | C03-R05；用户明确更正需看语义，不重复无意义确认 | 已确认候选 |
| S05 | 调用保存/纠正/删除并验证回执 | C03-R06/G05，幂等和失效关联 | 实际变更状态 |
| S06 | 返回必要片段并提示受影响任务 | C03-R07；不静默改已选计划，不承诺未建成存储 | profile_memory_result |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| retrieved / changes | 相关记录或确切差异，不泄露其他资料 |
| provenance / validity | 来源、有效期、确认与替代关系 |
| persistence | 实际操作、回执、失败及是否已生效 |
| affected_tasks | 可能需要用户重算的计划，不自动执行未授权任务 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "retrieved": [],
  "changes": [
    {
      "field": "income_schedule",
      "state": "candidate"
    }
  ],
  "persistence": {
    "status": "not_persisted",
    "receipt": null
  },
  "affected_tasks": []
}
```

## 5. 工具与其他 Skill 的衔接

- 已有：get_user_choice；ADK 具备记忆接入抽象
- 拟议：profile.read/write/correct、memory.search/save/delete、business_fact.router；目前尚无完整持久记忆闭环

点号形式均为拟议逻辑能力别名；后续可实现为普通 Tools 或 MCP，但不得直接在运行时调用未注册名称。未实现能力只产生明确缺口，不通过脚本绕过权限或自行连库。原生 Skill 资源工具与业务查询工具分别由当前配置提供；不能因加载入口就假定所有依赖可用。

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 8. 验收场景（设计，尚未运行）

| 场景 | 输入条件 | 期望行为 |
|---|---|---|
| 复用画像 | 有仍有效的已确认收入周期 | 不重复问 |
| 过期数据 | 旧收入不确定 | 标时效并必要时核实 |
| 更正事实 | 用户改收入 | 旧值关联替代，不继续引用 |
| 持久化失败 | 写入超时 | 不承诺记住 |
| 删除部分失败 | 摘要删了索引未删 | 报告真实部分状态 |
| 隔离 | 另一用户命中相似信息 | 不返回任何他人私有资料 |

用户补充规则后需把上述期望转成可核对样例：输入、适用规则版本、工具返回、交互答案、最终输出及不能执行的动作。现阶段不为草案运行无关应用回归。
