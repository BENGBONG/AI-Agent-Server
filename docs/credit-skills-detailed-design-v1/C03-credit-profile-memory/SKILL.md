# 画像与记忆（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

按当前用户与任务读取相关画像/长期记忆，并整理、确认、纠正或删除明确表达与核验过的信息。

账务真值由业务数据管理；不保存模型推测；没有持久化工具不承诺下次记得。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 明确当前任务与信息用途，校验用户范围。C03-R01，后端身份；无关画像不检索；产出：可处理范围。
2. 分类业务事实、画像或长期记忆。C03-R02；账单更新交 B01，避免双写真值；产出：目标存储类别。
3. 按任务检索并检查有效期和冲突。C03-R03/C03-R04，G02/G03；记忆不能替当前余额；产出：相关片段/候选差异。
4. 必要变更通过 get_user_choice 确认。C03-R05；用户明确更正需看语义，不重复无意义确认；产出：已确认候选。
5. 调用保存/纠正/删除并验证回执。C03-R06/G05，幂等和失效关联；产出：实际变更状态。
6. 返回必要片段并提示受影响任务。C03-R07；不静默改已选计划，不承诺未建成存储；产出：profile_memory_result。

## 工具和结果

- 已有：get_user_choice；ADK 具备记忆接入抽象
- 拟议：profile.read/write/correct、memory.search/save/delete、business_fact.router；目前尚无完整持久记忆闭环

拟议能力名不是可直接调用的现有工具。只能使用当前运行环境真实提供的工具；缺失时说明影响，不能自行假定存储、计算或外部动作成功。已获得的数据和来源传回主 Agent，由它按用户目标选择后续 Skill。

输出区分已证实、待核实、缺失和实际动作状态。取消、冲突或等待中不把计划当执行完成。字段、证据与完成条件见详细设计第 4 节，按业务规则表和已确认事实解释，不杜撰结果。
