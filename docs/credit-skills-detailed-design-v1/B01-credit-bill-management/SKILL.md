# 账单管理（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

查询、录入、核对和更正贷款及分期账单；用于查询应还/已还/到期、提交账单或修改记录。

还款资金排序交 B02；专项费用交 B03；付款状态争议交 B04。单纯查询不自动进入保存。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 识别查询、录入、更正或核对及目标账期。范围不明确且影响结果时 C01；不擅定全历史；产出：任务范围。
2. 查现有贷款、账单和最新状态。不可用/无权限与无记录分开；数据时效 G02；产出：账务快照。
3. 需要时加载 C02 提取候选，C01 只补缺口。最小字段 B01-R01、日期与金额口径 B01-R02/B01-R04；产出：候选账单。
4. 按来源和业务标识对账、识别重复。合并 B01-R03、冲突 G03/B01-R05；未定不覆盖；产出：新增/修改差异。
5. 展示关键差异，调用 get_user_choice。确认内容与版本一致；修改回 S03，取消不写；产出：确认结果。
6. 调用保存/更新服务并重读。幂等与写入失败处理 B01-R06；无回执不宣称保存；产出：实际保存结果。
7. 汇总账单、待核实项和可选后续。展示 B01-R07；用户要规划再 B02；产出：bill_summary / bill_review。

## 工具和结果

- 已有：list_uploaded_files、parse_uploaded_file、get_beijing_time、get_user_choice
- 拟议：loan.query、bill.query、bill.save_confirmed、bill.correct；用户范围由后端注入

拟议能力名不是可直接调用的现有工具。只能使用当前运行环境真实提供的工具；缺失时说明影响，不能自行假定存储、计算或外部动作成功。已获得的数据和来源传回主 Agent，由它按用户目标选择后续 Skill。

输出区分已证实、待核实、缺失和实际动作状态。取消、冲突或等待中不把计划当执行完成。字段、证据与完成条件见详细设计第 4 节，按业务规则表和已确认事实解释，不杜撰结果。
