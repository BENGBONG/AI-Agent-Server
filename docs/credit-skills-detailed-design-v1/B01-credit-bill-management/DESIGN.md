# B01 账单管理：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-bill-management`
**目标：** 查询、录入、核对和更正贷款及分期账单；用于查询应还/已还/到期、提交账单或修改记录。
**职责边界：** 还款资金排序交 B02；专项费用交 B03；付款状态争议交 B04。单纯查询不自动进入保存。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| operation | enum | 必需 | query / create / update / reconcile；从用户目标识别 |
| loan_ref / bill_ref | opaque ID / null | 定位单笔时 | 只能引用当前用户可见记录；未知时不能编 ID |
| institution / product | object | 新建时按 B01-R01 | 区分平台、贷款方和产品名；来自合同或核验材料 |
| period / due_at | date / null | 新建时按 B01-R01 | 账期和到期日分开，日期粒度、日界线由 G08 定义 |
| amounts | object<decimal-string> | 金额查询/录入 | 应还、本金、利息、费用、已还、待还分别保留；未知不是 0 |
| payment_state | enum / unknown | 状态查询/更正 | 支付、入账与结清分层；不得仅凭截图结清 |
| source_refs / as_of | array / timestamp | 所有事实 | 原文件、业务记录、用户陈述及各自有效日期 |
| candidate_changes | array | 新增/修改 | 旧值、新值、证据、待确认字段和冲突记录 |
| confirmation / write_receipt | object / null | 保存分支 | 确认绑定候选版本，实际保存需回执与重读 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 识别查询、录入、更正或核对及目标账期 | 范围不明确且影响结果时 C01；不擅定全历史 | 任务范围 |
| S02 | 查现有贷款、账单和最新状态 | 不可用/无权限与无记录分开；数据时效 G02 | 账务快照 |
| S03 | 需要时加载 C02 提取候选，C01 只补缺口 | 最小字段 B01-R01、日期与金额口径 B01-R02/B01-R04 | 候选账单 |
| S04 | 按来源和业务标识对账、识别重复 | 合并 B01-R03、冲突 G03/B01-R05；未定不覆盖 | 新增/修改差异 |
| S05 | 展示关键差异，调用 get_user_choice | 确认内容与版本一致；修改回 S03，取消不写 | 确认结果 |
| S06 | 调用保存/更新服务并重读 | 幂等与写入失败处理 B01-R06；无回执不宣称保存 | 实际保存结果 |
| S07 | 汇总账单、待核实项和可选后续 | 展示 B01-R07；用户要规划再 B02 | bill_summary / bill_review |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| bills[] | 贷款/账单引用、账期、到期日、金额组成、状态、证据 |
| totals | 分币种的合计及覆盖范围；不混加应还总额与本金利息 |
| changes / unresolved | 差异、冲突、缺失、保存结果及回执 |
| freshness | 查询时点、记录有效时点和过期说明 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "bills": [
    {
      "bill_ref": "example_bill_1",
      "currency": "CNY",
      "due_at": "2026-11-05",
      "amount_due": "1200.00",
      "posting_state": "unknown",
      "source_refs": [
        "example_source"
      ]
    }
  ],
  "totals": {
    "CNY": {
      "amount_due": "1200.00",
      "coverage": "本次仅一笔合成账单"
    }
  },
  "write_state": "not_requested"
}
```

点号形式均为拟议逻辑能力别名；后续可实现为普通 Tools 或 MCP，但不得直接在运行时调用未注册名称。未实现能力只产生明确缺口，不通过脚本绕过权限或自行连库。原生 Skill 资源工具与业务查询工具分别由当前配置提供；不能因加载入口就假定所有依赖可用。

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 8. 验收场景（设计，尚未运行）

| 场景 | 输入条件 | 期望行为 |
|---|---|---|
| 查询完整账单 | 已有两笔已确认记录 | 只查和展示，不重复确认或新增 |
| 缺到期日 | 截图仅有金额 | 只补缺失字段，确认前不伪造日期 |
| 重复上传 | 同一期账单两张截图 | 提示关联，不重复写入 |
| 来源冲突 | 用户说结清，系统未入账 | 保留冲突，交 B04 核实 |
| 保存超时后重试 | 已确认候选与幂等键相同 | 查询既有结果或幂等重试，不新增第二笔 |
| 不触发 | 用户只问客服电话 | 转 B05，不要求先建全量账单 |

用户补充规则后需把上述期望转成可核对样例：输入、适用规则版本、工具返回、交互答案、最终输出及不能执行的动作。现阶段不为草案运行无关应用回归。

以下为定稿后拟生成的结构，当前只存在本文件第 1 节说明的设计文件。DESIGN.md 与业务审查状态保留在设计区；正式包是否携带已定稿规则摘要，应在打包时确认，不复制未填写表投入运行。

| 规划资源 | 内容章节 / 输入输出 | 规则依据与边界 |
|---|---|---|
| references/bill-fields.md | 字段与必填条件 → 金额组成/未知值 → 状态层次 → 证据字段 → 正反例 | B01-R01/B01-R02/B01-R04/B01-R05；具体规则待填写 |
| references/reconciliation.md | 贷款/账期关联键 → 确定重复/疑似重复 → 来源冲突 → 修改差异 → 用户核验 → 幂等保存 | B01-R03/B01-R05/B01-R06，G03 |
| scripts/validate_bill.py | 输入：候选明细、币种、已定义金额关系和适用规则版本。输出：字段错误、合计不一致、缺失/未知及校验状态；不返回已保存状态。 | 未知不补零、金额关系缺失不硬校验；部分还款/总额含费用用例待业务给出 |

脚本执行契约（设计）：以明确传入 JSON 为输入，不读取宿主资料或密钥；输出结构化校验结果，含 checks / errors / missing_fields / rule_version。业务资料不完整是可解释结果，不用通用异常吞掉。格式/运行失败保留实际错误；超时/资源限制遵守已配置执行器。没有按需脚本输入输出能力时，后续接入需先设计适配，不能把本契约当现有原生工具签名。所有输出由工具结果交回主任务，脚本不写正式业务数据库。
