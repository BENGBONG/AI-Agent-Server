# 协商辅助（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

围绕用户真实困难和可承担还款额准备协商目标、候选诉求、沟通材料与跟进计划。

不保证减免/延期、不捏造困难；未接通执行服务时只准备材料；投诉不是默认下一步。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 确认当前目标及待协商合同。B06-R01/B06-R02；多合同范围由用户明确；产出：协商任务。
2. 核实债务、必要困难事实与偿付预算。B06-R03/B06-R04，B01/B02/C01 按需加载；产出：事实与约束。
3. 查机构适用流程与官方渠道。B05，B06-R05；查不到不承诺可协商；产出：联系及材料要求。
4. 准备可承担候选诉求与代价。不预设减免成功率；B06-R02/B06-R03；产出：候选方案。
5. 用 get_user_choice 选择并核验陈述。可改/取消；用户选择不等于已向机构提交；产出：选定草案。
6. 生成沟通说明、材料目录与下一步。B06-R06；若无执行工具输出准备完成；产出：negotiation_pack。
7. 按真实反馈更新跟进状态。B06-R07；自述和官方反馈分别记录；产出：案件进展/待办。

## 工具和结果

- 已有：get_user_choice、搜索抓取、文件解析
- 拟议：bill.query、cashflow.calculate、negotiation.policy、case.save/track；发送/提交待独立接入

拟议能力名不是可直接调用的现有工具。只能使用当前运行环境真实提供的工具；缺失时说明影响，不能自行假定存储、计算或外部动作成功。已获得的数据和来源传回主 Agent，由它按用户目标选择后续 Skill。

输出区分已证实、待核实、缺失和实际动作状态。取消、冲突或等待中不把计划当执行完成。字段、证据与完成条件见详细设计第 4 节，按业务规则表和已确认事实解释，不杜撰结果。
