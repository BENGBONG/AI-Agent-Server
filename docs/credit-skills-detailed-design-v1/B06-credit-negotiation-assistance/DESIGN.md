# B06 协商辅助：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-negotiation-assistance`
**目标：** 围绕用户真实困难和可承担还款额准备协商目标、候选诉求、沟通材料与跟进计划。
**职责边界：** 不保证减免/延期、不捏造困难；未接通执行服务时只准备材料；投诉不是默认下一步。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| loan / debt_snapshot | reference + object | 具体协商必需 | 账务时点、合同与争议项 |
| negotiation_goal | string/object | 必需 | 延期、分期或其他用户目标，不假定机构均支持 |
| hardship_statement | string / null | 需要说明困难时 | 用户真实表述；区分客观事实与个人期望 |
| affordable_schedule | array / null | 提出金额方案时 | 预算和可承担金额/日期及确定性 |
| prior_contacts | array | 有历史沟通时 | 已联系时间、对方身份、承诺和实际回执 |
| materials / contact_refs | array | 生成方案时 | 必要证据和核验后的官方触达方式 |
| selected_proposal / consent | object / null | 选择/外部动作时 | 选择方案、发信和转交资料分别识别 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 确认当前目标及待协商合同 | B06-R01/B06-R02；多合同范围由用户明确 | 协商任务 |
| S02 | 核实债务、必要困难事实与偿付预算 | B06-R03/B06-R04，B01/B02/C01 按需加载 | 事实与约束 |
| S03 | 查机构适用流程与官方渠道 | B05，B06-R05；查不到不承诺可协商 | 联系及材料要求 |
| S04 | 准备可承担候选诉求与代价 | 不预设减免成功率；B06-R02/B06-R03 | 候选方案 |
| S05 | 用 get_user_choice 选择并核验陈述 | 可改/取消；用户选择不等于已向机构提交 | 选定草案 |
| S06 | 生成沟通说明、材料目录与下一步 | B06-R06；若无执行工具输出准备完成 | negotiation_pack |
| S07 | 按真实反馈更新跟进状态 | B06-R07；自述和官方反馈分别记录 | 案件进展/待办 |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| fact_summary | 债务、预算、困难、证据和未核实部分 |
| proposal | 用户选定目标、金额日期、条件和现实局限 |
| communication_draft / materials | 真实陈述、具体诉求、证据目录 |
| follow_up | 渠道、下一步、反馈、实际执行/受理状态 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "proposal": {
    "goal": "待用户明确",
    "payment_schedule": null
  },
  "communication_draft": "仅为合成结构示例",
  "follow_up": {
    "status": "draft",
    "submitted": false
  },
  "missing_fields": [
    "协商目标及必要预算"
  ]
}
```

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |
