## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| origin_task / return_to | references | 必需 | 关联主任务与待恢复步骤，不能新建不相关任务 |
| required_fields | array<field_spec> | 必需 | 字段类型、用途、必填条件、选项/单位及规则 ID |
| known_values / source_refs | object | 必需 | 已有答案、来源、确认与时效 |
| missing / conflicts | arrays | 触发必需 | 只针对缺失或影响任务的冲突 |
| question_groups | array | 提问时 | 按依赖与用户负担分批，不预设批大小 |
| request_ref / answer | object | 交互等待/恢复 | 服务层 request/user/session/run/call 关联 |
| refused / confirmation | objects | 回传时 | 未提供、取消、修改与确认值分别保留 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 验证主任务和必要字段目的 | C01-R01；没有任务目的不开始采集 | 采集范围 |
| S02 | 复用已有有效答案并核对冲突 | G02/G03，C01-R02；不重复确认无变化内容 | 真实缺口 |
| S03 | 按依赖组织选择、表单、上传或开放问答 | C01-R03/C01-R04；已有工具能做什么就如实呈现 | 交互请求 |
| S04 | 等待真实回复并校验类型、单位与含义 | C01-R05；无答案不继续，重复提交靠服务幂等 | 候选字段 |
| S05 | 关键选择/确认用 get_user_choice | C01-R06；可修改/取消，确认绑定值版本 | confirmed_fields |
| S06 | 带缺失/拒绝/来源交回原任务 | 不隐含落库或第三方授权 | 主任务恢复或取消 |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| values[] | 字段、类型、值、来源、确认和时效 |
| missing / refused / conflicts | 不能把拒绝和未知变成 0/否 |
| interaction | 请求关联、等待/取消/完成状态 |
| return_to | 原任务和恢复步骤；不包含伪造调用 ID |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "values": [
    {
      "field": "due_at",
      "value": null,
      "confirmation": "pending"
    }
  ],
  "missing": [
    "due_at"
  ],
  "refused": [],
  "return_to": "原账单任务 S03",
  "status": "waiting_user"
}
```

## 5. 工具与其他 Skill 的衔接

- 已有：get_user_choice；可使用现有对话及附件入口
- 拟议：request_user_fields、request_user_upload、interaction.persist/resume；名称仅是能力设计

点号形式均为拟议逻辑能力别名；后续可实现为普通 Tools 或 MCP，但不得直接在运行时调用未注册名称。未实现能力只产生明确缺口，不通过脚本绕过权限或自行连库。原生 Skill 资源工具与业务查询工具分别由当前配置提供；不能因加载入口就假定所有依赖可用。

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 8. 验收场景（设计，尚未运行）

| 场景 | 输入条件 | 期望行为 |
|---|---|---|
| 已有答案 | 用户刚报金额日期 | 不再重复问 |
| 自由金额 | 需用户填任意金额 | 不用几个数值选项限制 |
| 等待中 | 工具未有回传 | 不代填 |

| 不触发 | 主任务信息充分 | 不启动采集 |

用户补充规则后需把上述期望转成可核对样例：输入、适用规则版本、工具返回、交互答案、最终输出及不能执行的动作。现阶段不为草案运行无关应用回归。
