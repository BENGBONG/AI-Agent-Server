# 信息采集（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

在已确定任务中补齐必需字段、消除歧义并交互确认；不独立开启无边界画像采集。

已有有效且已明确表达的信息不重复询问；开放原因可对话，不将自由金额伪装成有限选择。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 验证主任务和必要字段目的。C01-R01；没有任务目的不开始采集；产出：采集范围。
2. 复用已有有效答案并核对冲突。G02/G03，C01-R02；不重复确认无变化内容；产出：真实缺口。
3. 按依赖组织选择、表单、上传或开放问答。C01-R03/C01-R04；已有工具能做什么就如实呈现；产出：交互请求。
4. 等待真实回复并校验类型、单位与含义。C01-R05；无答案不继续，重复提交靠服务幂等；产出：候选字段。
5. 关键选择/确认用 get_user_choice。C01-R06；可修改/取消，确认绑定值版本；产出：confirmed_fields。
6. 带缺失/拒绝/来源交回原任务。不隐含落库或第三方授权；产出：主任务恢复或取消。

## 工具和结果

- 已有：get_user_choice；可使用现有对话及附件入口
- 拟议：request_user_fields、request_user_upload、interaction.persist/resume；名称仅是能力设计

拟议能力名不是可直接调用的现有工具。只能使用当前运行环境真实提供的工具；缺失时说明影响，不能自行假定存储、计算或外部动作成功。已获得的数据和来源传回主 Agent，由它按用户目标选择后续 Skill。

输出区分已证实、待核实、缺失和实际动作状态。取消、冲突或等待中不把计划当执行完成。字段、证据与完成条件见详细设计第 4 节，按业务规则表和已确认事实解释，不杜撰结果。
