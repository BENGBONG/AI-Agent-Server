# B03 费用分析：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-cost-analysis`
**目标：** 解释并按适用规则计算利息、罚息、附加费用和提前还款成本；用于费用疑问、核算及同口径比较。
**职责边界：** 不凭费用结果作违法认定；预算安排交 B02；争议投诉交 B07。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| analysis_type | enum | 必需 | interest / overdue / prepayment / comparison / explain |
| contract_ref / product | reference | 具体核算必需 | 适用合同和产品，不能只用平台名称定规则 |
| principal_base | decimal-string | 计算必需 | 剩余本金/逾期本金/应还额等不同基数必须区分 |
| rate / rate_unit | decimal-string + enum | 计算必需 | 日/月/年、单利/复利或现金流口径，缺项不能补 |
| start_at / end_at | date | 计息必需 | 起止包含关系与宽限按 B03-R02/B03-R03 |
| payment_events | array | 部分还款时 | 支付与入账何时减少计息基数按规则 |
| fees / waivers | array | 有附加费用时 | 项目、金额、条件及是否已确认 |
| rule_version / evidence | object | 所有核算 | 来源、适用期、公式/舍入与估算属性 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 确定解释、核算或比较的具体问题 | 问题类型 B03-R01；不能把说明当作核算完毕 | 分析范围 |
| S02 | 查合同、费用明细和适用规则 | G02/G03，B03-R02/B03-R06；新政策不自动替代旧合同 | 规则证据 |
| S03 | 检查基数、费率、日期、事件等参数 | B03-R02—B03-R05/B03-R08；缺规则只返回缺失项 | 可计算参数 |
| S04 | 调用确定性工具，独立校验单位和金额关系 | 计算服务失败不模型补算；保留公式及版本 | 计算明细 |
| S05 | 比较同口径方案或核对实际报价 | 比较 B03-R07；不适用时明确不可比 | 差异/不可比原因 |
| S06 | 给出解释、假设和证据；按意愿交接 | 发生争议可 B07；规则不足不输出精确罚息 | cost_breakdown / cost_comparison |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| inputs / formula | 基数、单位、日期、事件、公式和来源 |
| items[] / total | 分项、币种、金额、舍入及是否估算 |
| comparison | 同口径条件、差异与不可比原因 |
| missing_rules | 未定参数和因此不能完成的计算 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "analysis_type": "overdue",
  "items": [],
  "total": null,
  "missing_rules": [
    "适用费率",
    "计息基数",
    "起止及宽限规则"
  ],
  "is_estimate": true
}
```

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 8. 验收场景（设计，尚未运行）

| 场景 | 输入条件 | 期望行为 |
|---|---|---|
| 缺费率 | 只有欠款金额和逾期天数 | 不编造罚息 |

## 9. 规划运行包的完整结构与资源章节

以下为定稿后拟生成的结构，当前只存在本文件第 1 节说明的设计文件。DESIGN.md 与业务审查状态保留在设计区；正式包是否携带已定稿规则摘要，应在打包时确认，不复制未填写表投入运行。

```text
credit-cost-analysis/
├── SKILL.md
├── references/
│   ├── business-rules.md
│   ├── calculation-contract.md
│   └── comparison-basis.md
└── scripts/
    └── validate_cost_result.py
```

| 规划资源 | 内容章节 / 输入输出 | 规则依据与边界 |
|---|---|---|
| references/calculation-contract.md | 费用类型 → 必要参数 → 适用规则与事件 → 日期/单位/舍入 → 结果明细及误差 → 失败状态 | B03-R01—B03-R06/B03-R08；费率、起算和舍入不预填 |
| references/comparison-basis.md | 现金流边界 → 价格条件 → 年化口径 → 提前还款 → 不可比原因 → 展示 | B03-R07/B03-R08；未定不能生成统一最优排名 |
| scripts/validate_cost_result.py | 输入：适用规则版本、服务计算输入/分项/总计及已定义精度。输出：单位、求和、引用一致性问题。 | 不将校验脚本当正式计息引擎；无规则或服务失败不补计算结果 |

脚本执行契约（设计）：以明确传入 JSON 为输入，不读取宿主资料或密钥；输出结构化校验结果，含 checks / errors / missing_fields / rule_version。业务资料不完整是可解释结果，不用通用异常吞掉。格式/运行失败保留实际错误；超时/资源限制遵守已配置执行器。没有按需脚本输入输出能力时，后续接入需先设计适配，不能把本契约当现有原生工具签名。所有输出由工具结果交回主任务，脚本不写正式业务数据库。
