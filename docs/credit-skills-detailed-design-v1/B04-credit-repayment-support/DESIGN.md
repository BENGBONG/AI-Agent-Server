# B04 还款支持：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-repayment-support`
**目标：** 查询适用还款方式，排查扣款失败、支付未入账、重复扣款等问题，给出有来源的操作和处理路径。
**职责边界：** 不直接扣款/退款；不将支付截图自动视为入账或结清；联系主体交 B05。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| issue_type | enum / unknown | 必需 | 方式咨询、失败、未入账、重复扣款、退款或其他 |
| loan_ref / bill_ref | reference | 定位具体问题 | 当前用户贷款与账期，必要时 C01 确认 |
| channel / attempted_at | string + timestamp | 故障时 | 实际支付渠道、操作时间、错误提示 |
| transaction_refs | array | 交易核对时 | 敏感标识按服务要求提交，不索取支付口令 |
| payment / posting / bill_state | separate states | 故障核验 | 三类状态及各自查询时间，不合并 |
| proof_refs | array | 需要凭证时 | 用户私有材料，C02 提取必要字段 |
| method_rules / expected_window | object / null | 指导时 | 官方方式、条件、到账范围和适用版本 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 区分咨询与故障，识别贷款及渠道 | 问题分类 B04-R01；未知问题允许开放叙述 | 问题范围 |
| S02 | 查还款方式、到账规则和业务状态 | B04-R02/B04-R03；没有查询接口明确局限 | 规则及状态 |
| S03 | 有必要时核验凭证并对齐交易 | B04-R04；支付/入账/结清分开，疑似重复先查证 | 已证实/未知事实 |
| S04 | 按故障分支提供下一步 | 错误提示、等待、人工核对按 B04-R03/B04-R05 | 排查清单 |
| S05 | 存在分支选择时 get_user_choice | 取消不继续，重复扣款不盲目建议再次付款 | 用户选择 |
| S06 | 输出处理说明、需要材料和正式渠道 | B04-R06；联系 B05，争议 B07；无回执不说退款成功 | repayment_support |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| known_states | 支付、入账和账单状态分别展示 |
| steps[] | 操作、前提、官方来源与何时转人工 |
| required_materials | 为当前问题必要的凭证清单 |
| next_channel | 适用处理方、渠道及未知部分 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "issue_type": "paid_not_posted",
  "known_states": {
    "payment": "success",
    "posting": "unknown",
    "bill": "unknown"
  },
  "steps": [
    "核对官方入账状态与交易标识"
  ],
  "required_materials": [],
  "external_action": "not_performed"
}
```

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |
