# 还款支持（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

查询适用还款方式，排查扣款失败、支付未入账、重复扣款等问题，给出有来源的操作和处理路径。

不直接扣款/退款；不将支付截图自动视为入账或结清；联系主体交 B05。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 区分咨询与故障，识别贷款及渠道。问题分类 B04-R01；未知问题允许开放叙述；产出：问题范围。
2. 查还款方式、到账规则和业务状态。B04-R02/B04-R03；没有查询接口明确局限；产出：规则及状态。
3. 有必要时核验凭证并对齐交易。B04-R04；支付/入账/结清分开，疑似重复先查证；产出：已证实/未知事实。
4. 按故障分支提供下一步。错误提示、等待、人工核对按 B04-R03/B04-R05；产出：排查清单。
5. 存在分支选择时 get_user_choice。取消不继续，重复扣款不盲目建议再次付款；产出：用户选择。
6. 输出处理说明、需要材料和正式渠道。B04-R06；联系 B05，争议 B07；无回执不说退款成功；产出：repayment_support。
