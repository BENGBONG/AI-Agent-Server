# B02 还款规划：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-repayment-planning`
**目标：** 结合账单、资金余额、收入到账与必要支出制定还款计划；用于还款排序、月度安排和资金缺口分析。
**职责边界：** 不自动推荐新贷款；协商执行归 B06；费用公式归 B03。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| planning_window | date range | 必需 | 明确开始/截止时点；缺省区间待 B02-R01 |
| bills_snapshot | array | 计算必需 | 已确认账单及时间覆盖、状态、版本 |
| available_funds | money by currency | 计算必需 | 真正可动用余额，区分授信额度和自有资金 |
| income_schedule | array<date,money> | 跨收入日计划 | 确定/不确定收入分开，不合并重复来源 |
| essential_expenses | array<date,money> | 预算必需 | 生活支出和其他必须付款的时间序列 |
| reserve | money / null | 按 B02-R02 | 用户保留资金，不能默认为可全部偿债 |
| goal / constraints | enum/object | 方案取舍 | 用户目标、不可延期事项、允许的方案类型 |
| rules_snapshot | object | 涉及规则时 | 宽限、提前还款、最低额、抵扣顺序均需适用规则 |
| selected_plan / confirmation | object / null | 用户选择时 | 仅表示选方案，不等于授权划款 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 明确规划区间和用户目标 | 默认目标 B02-R01；无关偏好不强制收集 | 目标与范围 |
| S02 | 读取账单及画像相关片段 | 新鲜度 G02；缺账单回 B01，保持任务上下文 | 输入快照 |
| S03 | 补齐资金时间表、必要支出和保留资金 | B02-R02/B02-R03；缺失只提供明确条件性示例 | 可计算现金流 |
| S04 | 查询适用规则并调用计划计算 | 优先顺序 B02-R04、不可行分支 B02-R05；不用模型心算 | 方案与资金缺口 |
| S05 | 解释方案取舍并让用户选择 | 候选数与可选项 B02-R06；修改目标后重算 | 已选/未选方案 |
| S06 | 输出逐日/逐笔安排及假设 | 保存及复算 B02-R07；没有订阅服务不说将提醒 | repayment_plan |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| schedule[] | 到期日、建议准备/付款日、金额、对应账单、当日可用余额 |
| cash_gaps[] | 缺口日期、金额、原因及可行条件 |
| assumptions | 收入确定性、支出、保留资金与规则来源 |
| selection | 候选、用户已选与未执行状态 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "schedule": [],
  "cash_gaps": [
    {
      "date": "2026-11-05",
      "currency": "CNY",
      "amount": "300.00",
      "reason": "合成示例：收入晚于到期日"
    }
  ],
  "assumptions": [
    "合成样例，非正式还款建议"
  ],
  "selection": "not_selected"
}
```

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 8. 验收场景（设计，尚未运行）

| 场景 | 输入条件 | 期望行为 |
|---|---|---|
| 日期缺口 | 月收入够但工资晚于到期日 | 识别到期日缺口 |
| 保留资金 | 余额含生活费 | 不全部用于还债 |
| 不确定收入 | 奖金尚未确认 | 单列条件性场景 |
| 取消选择 | 用户拒绝候选 | 不保存为已选，不执行付款 |
| 无可行方案 | 所有日序资金不足 | 如实说明，不自动卖贷款 |
| 不触发 | 只查询一笔账单金额 | 由 B01 回答，不收集收入 |

用户补充规则后需把上述期望转成可核对样例：输入、适用规则版本、工具返回、交互答案、最终输出及不能执行的动作。现阶段不为草案运行无关应用回归。

## 9. 规划运行包的完整结构与资源章节

以下为定稿后拟生成的结构，当前只存在本文件第 1 节说明的设计文件。DESIGN.md 与业务审查状态保留在设计区；正式包是否携带已定稿规则摘要，应在打包时确认，不复制未填写表投入运行。

```text

├── references/
│   ├── business-rules.md
│   ├── cashflow-model.md
│   └── plan-explanation.md

    └── check_cashflow.py
```

| 规划资源 | 内容章节 / 输入输出 | 规则依据与边界 |
|---|---|---|
| references/cashflow-model.md | 规划区间 → 余额/收入/支出/保留资金 → 到期事件 → 条件性资金 → 缺口与方案可行性 | B02-R01—B02-R05；与 B03 共享费用规则版本，不复制公式 |
| references/plan-explanation.md | 用户目标 → 方案假设 → 逐日差异 → 缺口说明 → 方案选择 → 修改和复算 | B02-R06/B02-R07 |
| scripts/check_cashflow.py | 输入：按币种分开的期初余额、日期事件、保留资金、已计算计划。输出：逐日余额、缺口、守恒校验及缺少参数。 | 不在脚本内设置默认优先级；测试收入晚到、同日多事件与不确定收入 |

脚本执行契约（设计）：以明确传入 JSON 为输入，不读取宿主资料或密钥；输出结构化校验结果，含 checks / errors / missing_fields / rule_version。业务资料不完整是可解释结果，不用通用异常吞掉。格式/运行失败保留实际错误；超时/资源限制遵守已配置执行器。没有按需脚本输入输出能力时，后续接入需先设计适配，不能把本契约当现有原生工具签名。所有输出由工具结果交回主任务，脚本不写正式业务数据库。
