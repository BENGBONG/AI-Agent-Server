# 材料核验（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

按任务目的解析私有截图/文件、抽取候选事实、保留证据位置并核对重复和冲突。

不无限抽取全部个人信息，不把抽取内容自动当已确认事实，不在此独立决定业务保存。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 校验任务目的、文件权限和材料类型。C02-R01，不能读取全电脑文件；产出：范围与引用。
2. 调用列表/解析工具，检查覆盖和质量。C02-R02/C02-R03；缺页截断不能标完整；产出：解析及局限。
3. 按材料类型提取必要候选字段。C02-R01/C02-R04；未知与 0 区分；产出：候选事实。
4. 规范单位/日期并附原文位置。C02-R04；保留原始值和推导依据；产出：可追溯候选。
5. 和现有事实比对重复与冲突。C02-R05，G03；不直接覆盖或合并；产出：核验差异。
6. 必要时 C01 确认，带证据交回主任务。C02-R06；保存由业务分支和工具执行；产出：evidence_review。

- 拟议：domain.extract、evidence.link、duplicate.detect、private_file.store；不同格式覆盖须样例验收

拟议能力名不是可直接调用的现有工具。只能使用当前运行环境真实提供的工具；缺失时说明影响，不能自行假定存储、计算或外部动作成功。已获得的数据和来源传回主 Agent，由它按用户目标选择后续 Skill。

输出区分已证实、待核实、缺失和实际动作状态。取消、冲突或等待中不把计划当执行完成。字段、证据与完成条件见详细设计第 4 节，按业务规则表和已确认事实解释，不杜撰结果。
