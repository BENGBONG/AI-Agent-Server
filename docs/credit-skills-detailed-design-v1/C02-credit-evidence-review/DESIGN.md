# C02 材料核验：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-evidence-review`
**目标：** 按任务目的解析私有截图/文件、抽取候选事实、保留证据位置并核对重复和冲突。
**职责边界：** 不无限抽取全部个人信息，不把抽取内容自动当已确认事实，不在此独立决定业务保存。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| origin_task / extraction_goal | references + string | 必需 | 明确要核验什么及交回哪一步 |
| artifact_refs | array | 必需 | 当前用户可访问上传引用，不接受任意主机路径 |
| document_type / scope | object | 解析前 | 材料类型、所需页/表/区间，未知先识别 |
| parse_result / parse_version | object | 解析后 | 实际内容、覆盖、截断、失败或扫描识别局限 |
| candidate_facts | array | 抽取后 | 原文值、标准化值、单位、来源、状态 |
| source_location / confidence | objects / null | 输出时 | 只有解析器提供才填坐标/置信度，不能自编 |
| existing_facts / conflicts | objects | 核对时 | 同贷款/账期/交易线索及冲突两侧证据 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 校验任务目的、文件权限和材料类型 | C02-R01，不能读取全电脑文件 | 范围与引用 |
| S02 | 调用列表/解析工具，检查覆盖和质量 | C02-R02/C02-R03；缺页截断不能标完整 | 解析及局限 |
| S03 | 按材料类型提取必要候选字段 | C02-R01/C02-R04；未知与 0 区分 | 候选事实 |
| S04 | 规范单位/日期并附原文位置 | C02-R04；保留原始值和推导依据 | 可追溯候选 |
| S05 | 和现有事实比对重复与冲突 | C02-R05，G03；不直接覆盖或合并 | 核验差异 |
| S06 | 必要时 C01 确认，带证据交回主任务 | C02-R06；保存由业务分支和工具执行 | evidence_review |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| candidates[] | 字段、原文/标准化值、单位、证据及核验状态 |
| coverage / limitations | 已读与未读范围、扫描识别或截断局限 |
| duplicates / conflicts | 关联候选及两侧证据，不自动处理结论 |
| confirmation_state | 哪些已确认、待核验、不支持；与落库分离 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json

    }
  ],
  "coverage": "partial",

    "字段及位置待实际解析"

}
```

## 5. 工具与其他 Skill 的衔接

- 已有：list_uploaded_files、parse_uploaded_file、get_user_choice
- 拟议：domain.extract、evidence.link、duplicate.detect、private_file.store；不同格式覆盖须样例验收

点号形式均为拟议逻辑能力别名；后续可实现为普通 Tools 或 MCP，但不得直接在运行时调用未注册名称。未实现能力只产生明确缺口，不通过脚本绕过权限或自行连库。原生 Skill 资源工具与业务查询工具分别由当前配置提供；不能因加载入口就假定所有依赖可用。

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 8. 验收场景（设计，尚未运行）

| 场景 | 输入条件 | 期望行为 |

## 9. 规划运行包的完整结构与资源章节

以下为定稿后拟生成的结构，当前只存在本文件第 1 节说明的设计文件。DESIGN.md 与业务审查状态保留在设计区；正式包是否携带已定稿规则摘要，应在打包时确认，不复制未填写表投入运行。

```text
credit-evidence-review/
├── SKILL.md
├── references/
│   ├── business-rules.md
│   ├── material-mapping.md
│   └── evidence-status.md
└── scripts/
    └── check_extracted_fields.py
```

| 规划资源 | 内容章节 / 输入输出 | 规则依据与边界 |
|---|---|---|
| references/material-mapping.md | 任务/材料类型 → 所需字段 → 页/表范围 → 原文位置 → 允许标准化 → 不能推断 | C02-R01/C02-R04；征信专有口径由 B08 定义 |
| references/evidence-status.md | 原件/解析/候选/用户确认/机构回执分层 → 覆盖状态 → 去重冲突 → 材料保留 | C02-R02/C02-R03/C02-R05/C02-R06；unknown 与真实置信度分开 |
| scripts/check_extracted_fields.py | 输入：抽取字段、原文证据、已定义类型与关系。输出：类型/单位问题、缺失和关系不一致。 | 不模拟 OCR 置信度；不做正式业务保存；未知关系不硬判错误 |

脚本执行契约（设计）：以明确传入 JSON 为输入，不读取宿主资料或密钥；输出结构化校验结果，含 checks / errors / missing_fields / rule_version。业务资料不完整是可解释结果，不用通用异常吞掉。格式/运行失败保留实际错误；超时/资源限制遵守已配置执行器。没有按需脚本输入输出能力时，后续接入需先设计适配，不能把本契约当现有原生工具签名。所有输出由工具结果交回主任务，脚本不写正式业务数据库。
