# B09 产品匹配：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-loan-matching`
**目标：** 在用户明确有融资或产品比较需求时，按必要资料、产品准入、偿付能力与用户偏好筛选和比较合作贷款产品。
**职责边界：** 还款困难不自动触发营销；未知条件不当通过；不承诺授信、额度、利率或放款。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| intent / purpose | string | 必需 | 明确融资或产品比较意图，不从逾期推断 |
| amount / currency / term / needed_at | money + duration + date | 筛选必需 | 金额、期限单位、资金需要时间 |
| region / eligibility_facts | object | 按产品要求 | 只收准入必要资料，证据与有效期齐全 |
| income / expenses / liabilities | cashflow objects | 偿付评估必需 | 与 B02 口径一致，不把未核实收入视为可用 |
| credit / asset_refs | private references | 特定产品必要且用途明确时 | 先用已有已确认信息，征信查询是独立动作 |
| preferences | object | 排序时 | 总成本/月供/方式/提前还款/放款时间等由用户表达 |
| catalog_snapshot | array + version | 匹配必需 | 合作范围、状态、价格条件、准入、规则、有效时间 |
| quote / missing_conditions / next_consent | objects | 展示及后续动作 | 可比/不可比、未知项、用户选择与申请授权分开 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 识别融资意图与具体需求 | B09-R01，用户目标不明先 C01；不自动触发 | 匹配任务 |
| S02 | 读取相关画像、补产品必要条件 | B09-R02/B09-R03，征信/资产按需且用途明确 | 最小必要资料 |
| S03 | 查询有效合作目录并检查范围/时效 | B09-R04；未接目录不能假造可办理产品 | 可参与产品 |
| S04 | 执行硬性条件与偿付能力检查 | B09-R03/B09-R05；分满足、不满足、未知 | 候选/排除/待补 |
| S05 | 按用户目标比较成本和还款条件 | B09-R06/B09-R07；不可比不硬排，允许无推荐 | 比较结果 |
| S06 | 展示理由与未知项，get_user_choice 选后续 | B09-R08；选择了解不等于授权提交 | product_comparison |
| S07 | 只有实际动作工具和对应授权才执行 | 无工具则交付用户可自行操作的官方步骤 | 行动状态及回执 |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| scope / user_goals | 合作覆盖范围、用户目标与资料时点 |
| candidates[] | 匹配条件、成本口径、月供/方式、理由、未知项 |
| excluded / pending | 不满足与待补条件分开 |
| selection / action | 用户选择与第三方动作/查询/申请回执分别记录 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "scope": "示例，未接入合作目录",
  "candidates": [],
  "pending": [
    "产品目录",
    "明确准入及偿付规则"
  ],
  "selection": null,
  "action": {
    "application_submitted": false
  }
}
```

## 5. 工具与其他 Skill 的衔接

- 已有：get_user_choice、文件解析、搜索抓取（不等于合作目录）
- 拟议：product.catalog、eligibility.evaluate、affordability.calculate、cost.compare、profile.read；征信查询/申请/转交独立接入

点号形式均为拟议逻辑能力别名；后续可实现为普通 Tools 或 MCP，但不得直接在运行时调用未注册名称。未实现能力只产生明确缺口，不通过脚本绕过权限或自行连库。原生 Skill 资源工具与业务查询工具分别由当前配置提供；不能因加载入口就假定所有依赖可用。

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 9. 规划运行包的完整结构与资源章节

以下为定稿后拟生成的结构，当前只存在本文件第 1 节说明的设计文件。DESIGN.md 与业务审查状态保留在设计区；正式包是否携带已定稿规则摘要，应在打包时确认，不复制未填写表投入运行。

```text
credit-loan-matching/
├── SKILL.md
├── references/
│   ├── business-rules.md
│   ├── eligibility-model.md
│   └── ranking-model.md
└── scripts/
    └── check_match_results.py
```

| 规划资源 | 内容章节 / 输入输出 | 规则依据与边界 |
|---|---|---|
| references/eligibility-model.md | 用户意图 → 阶段必要字段 → 有效产品 → 准入三值判断 → 偿付条件 → 排除/待补原因 | B09-R01—B09-R05；阈值与产品规则动态维护 |
| references/ranking-model.md | 用户目标 → 可比口径 → 排序条件/权重 → 未知/并列/不可比 → 合作覆盖说明 → 用户选择 | B09-R06—B09-R08；合作收益不隐藏改变用户利益排序 |
| scripts/check_match_results.py | 输入：产品版本、规则评估、用户约束、候选比较。输出：缺字段、条件冲突、无依据排序、价格条件遗漏等校验。 | 不生成审批概率，不内置未定义负债率阈值；无合适产品是有效结果 |

脚本执行契约（设计）：以明确传入 JSON 为输入，不读取宿主资料或密钥；输出结构化校验结果，含 checks / errors / missing_fields / rule_version。业务资料不完整是可解释结果，不用通用异常吞掉。格式/运行失败保留实际错误；超时/资源限制遵守已配置执行器。没有按需脚本输入输出能力时，后续接入需先设计适配，不能把本契约当现有原生工具签名。所有输出由工具结果交回主任务，脚本不写正式业务数据库。
