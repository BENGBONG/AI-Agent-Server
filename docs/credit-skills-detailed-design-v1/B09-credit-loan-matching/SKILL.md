# 产品匹配（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

在用户明确有融资或产品比较需求时，按必要资料、产品准入、偿付能力与用户偏好筛选和比较合作贷款产品。

还款困难不自动触发营销；未知条件不当通过；不承诺授信、额度、利率或放款。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 识别融资意图与具体需求。B09-R01，用户目标不明先 C01；不自动触发；产出：匹配任务。
2. 读取相关画像、补产品必要条件。B09-R02/B09-R03，征信/资产按需且用途明确；产出：最小必要资料。
3. 查询有效合作目录并检查范围/时效。B09-R04；未接目录不能假造可办理产品；产出：可参与产品。
4. 执行硬性条件与偿付能力检查。B09-R03/B09-R05；分满足、不满足、未知；产出：候选/排除/待补。
5. 按用户目标比较成本和还款条件。B09-R06/B09-R07；不可比不硬排，允许无推荐；产出：比较结果。
6. 展示理由与未知项，get_user_choice 选后续。B09-R08；选择了解不等于授权提交；产出：product_comparison。
7. 只有实际动作工具和对应授权才执行。无工具则交付用户可自行操作的官方步骤；产出：行动状态及回执。

## 工具和结果

- 已有：get_user_choice、文件解析、搜索抓取（不等于合作目录）
- 拟议：product.catalog、eligibility.evaluate、affordability.calculate、cost.compare、profile.read；征信查询/申请/转交独立接入

拟议能力名不是可直接调用的现有工具。只能使用当前运行环境真实提供的工具；缺失时说明影响，不能自行假定存储、计算或外部动作成功。已获得的数据和来源传回主 Agent，由它按用户目标选择后续 Skill。

输出区分已证实、待核实、缺失和实际动作状态。取消、冲突或等待中不把计划当执行完成。字段、证据与完成条件见详细设计第 4 节，按业务规则表和已确认事实解释，不杜撰结果。
