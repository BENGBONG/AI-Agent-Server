# 投诉辅助（设计入口草案）

此文件位于设计目录，未导入 Agent。业务规则尚待填写，逻辑依赖尚有未实现项，不可仅凭该草案执行正式业务。本文中的“需确认”沿用用户已确认约定：使用 get_user_choice 并等待真实答案，不重复索取已有有效指令。

## 目标和边界

针对用户明确争议或投诉意图整理事实、证据、诉求，并查询匹配主体、事项及地区的官方投诉路径。

不默认升级所有问题为投诉，不替机构判定违法，不捏造证据或承诺受理。

## 使用方法

先检查当前任务、已知信息及可用工具。命中需要组织规则的分支时，读取 [业务规则](references/business-rules.md) 对应编号；如果仍待补充，只做不依赖它的查询/解释或返回必要缺口，不自己填规则。

不要一次加载全部参考资料。当前细节见 [详细设计](DESIGN.md)，正式打包时应将必要指令收敛为入口与按需参考，不把审查记录搬入每次模型上下文。

## 主流程

1. 明确争议目标及投诉意图。B07-R01；可解释疑问不自动转投诉；产出：任务目标。
2. 识别主体、事项与地区。B07-R02，按需 B05；机构不明先核实；产出：匹配条件。
3. 整理时间线、事实、费用和证据。B07-R03/B07-R04，C02/B03；未证事实单列；产出：材料底稿。
4. 查询适用官方渠道及受理条件。B07-R05；不能确认管辖不猜号码；产出：可用渠道。
5. 需要路径选择或核验材料时 get_user_choice。可改/取消，不重复确认已明确普通查询；产出：已选路径/草稿。
6. 输出投诉说明、证据目录和提交步骤。B07-R06；没有执行回执标未提交；产出：complaint_pack。

## 工具和结果

- 已有：搜索抓取、文件解析、get_user_choice
- 拟议：complaint.knowledge、case.track、private_evidence.query；真实提交另行接入

拟议能力名不是可直接调用的现有工具。只能使用当前运行环境真实提供的工具；缺失时说明影响，不能自行假定存储、计算或外部动作成功。已获得的数据和来源传回主 Agent，由它按用户目标选择后续 Skill。

输出区分已证实、待核实、缺失和实际动作状态。取消、冲突或等待中不把计划当执行完成。字段、证据与完成条件见详细设计第 4 节，按业务规则表和已确认事实解释，不杜撰结果。
