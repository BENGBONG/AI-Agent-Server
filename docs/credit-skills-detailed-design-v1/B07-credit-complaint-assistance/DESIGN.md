# B07 投诉辅助：详细设计

**状态：** 设计草案，业务规则待逐项补充，非运行包。
**拟议 Skill name：** `credit-complaint-assistance`
**目标：** 针对用户明确争议或投诉意图整理事实、证据、诉求，并查询匹配主体、事项及地区的官方投诉路径。
**职责边界：** 不默认升级所有问题为投诉，不替机构判定违法，不捏造证据或承诺受理。

## 2. 输入数据设计

[共同字段、身份、金额、时间、证据与状态约定](../00-common-design-and-rules.md) 适用于本表。字段是服务/Skill 交接草案，不意味着同名参数已在当前工具中注册。

| 字段 | 类型 | 必要条件 | 来源及校验 |
|---|---|---|---|
| dispute_type / goal | string/object | 必需 | 争议事实、希望解决方式与是否明确要投诉 |
| entities / jurisdiction_clues | object | 渠道匹配时 | 平台/贷款/服务/催收等角色和适用地区线索 |
| timeline | array<event> | 材料整理必需 | 每项时间、事件、来源，推测与事实区分 |
| amounts / related_records | array | 费用或付款争议时 | 相关账单、交易与费用解释 |
| evidence_refs | array | 每个争议点 | 可核验私有证据位置，缺失明确 |
| prior_resolution / desired_remedy | object | 按任务需要 | 曾与谁沟通、实际结果、用户诉求 |
| channel_requirements / receipt | object / null | 提交路径时 | 官方条件、材料、时效与真实提交回执 |

## 3. 处理步骤与分支

| 步骤 | 处理动作 | 分支 / 规则依赖 | 本步产出 |
|---|---|---|---|
| S01 | 明确争议目标及投诉意图 | B07-R01；可解释疑问不自动转投诉 | 任务目标 |
| S02 | 识别主体、事项与地区 | B07-R02，按需 B05；机构不明先核实 | 匹配条件 |
| S03 | 整理时间线、事实、费用和证据 | B07-R03/B07-R04，C02/B03；未证事实单列 | 材料底稿 |
| S04 | 查询适用官方渠道及受理条件 | B07-R05；不能确认管辖不猜号码 | 可用渠道 |
| S05 | 需要路径选择或核验材料时 get_user_choice | 可改/取消，不重复确认已明确普通查询 | 已选路径/草稿 |
| S06 | 输出投诉说明、证据目录和提交步骤 | B07-R06；没有执行回执标未提交 | complaint_pack |

交互需要真实回复才能恢复依赖步骤；无关步骤可继续。用户修改关键输入后，使依赖旧值的计算/确认失效，回到相应步骤而非重问全部信息。取消只终止未执行分支，已完成操作如需撤销须单独依据实际工具处理。

## 4. 输出与完成标准

| 结果字段 | 含义 |
|---|---|
| facts / disputed_points | 事实、争议解释、尚待证明内容 |
| timeline / evidence_index | 时间线与证据逐项对应 |
| draft / requested_remedy | 陈述和用户诉求，不代作法律结论 |
| channels / submission | 适用依据、官方入口、材料与真实状态 |

完成条件：用户当前问题所需的字段/证据和适用规则足够，所依赖工具真实成功。仅局部可答使用 partial；缺用户回复使用 waiting_user；缺系统能力/关键业务规则使用 blocked 或 partial，并指出影响范围。保存、提交、入账和结清等状态必须对应真实回执，不能由整体 completed 推导。

以下为 `data` 的合成结构示例；字段、金额和状态只演示设计，不是实测业务结果：

```json
{
  "facts": [],
  "disputed_points": [
    "合成示例：待核对费用"
  ],
  "draft": null,
  "channels": [],
  "submission": {
    "status": "not_submitted",
    "receipt": null
  }
}
```

## 5. 工具与其他 Skill 的衔接

- 已有：搜索抓取、文件解析、get_user_choice
- 拟议：complaint.knowledge、case.track、private_evidence.query；真实提交另行接入

点号形式均为拟议逻辑能力别名；后续可实现为普通 Tools 或 MCP，但不得直接在运行时调用未注册名称。未实现能力只产生明确缺口，不通过脚本绕过权限或自行连库。原生 Skill 资源工具与业务查询工具分别由当前配置提供；不能因加载入口就假定所有依赖可用。

跨 Skill 由主 Agent 负责加载与恢复；交接只传本任务必要的确认值、来源、缺口、当前步骤和动作状态。其他 Skill 未绑定时保留局部结果并说明依赖，不构造虚假的调用结果。

## 6. 异常及结束

| 情况 | 处理 |
|---|---|
| 来源超时 / 无权限 | 区分 unavailable / forbidden / missing，允许有证据的局部输出 |
| 字段冲突 / 不新鲜 | 保留来源、日期和冲突，按 G02/G03 及本 Skill 规则核实 |
| 用户不清楚 / 拒绝 / 取消 | 记录缺口及影响，不填默认值或假设同意 |
| 规则待定 | 仅限制依赖该规则的分支；不把用户个案确认当组织规则批准 |
| 工具回执丢失 | 查询动作状态或按服务幂等机制重试；不盲目重复写入/提交 |
| 无下一步执行能力 | 如实交付材料或说明，不宣称已保存、发送、受理或订阅 |

## 8. 验收场景（设计，尚未运行）

| 场景 | 输入条件 | 期望行为 |
|---|---|---|
| 费用争议 | 用户明确要投诉且证据完整 | 材料和费用核对一致 |
| 主体未知 | 只有平台展示名 | 先识别主体再选渠道 |
