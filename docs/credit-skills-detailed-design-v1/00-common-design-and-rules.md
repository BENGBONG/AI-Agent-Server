# 共同设计约定与全局业务规则

日期：2026-10-23。所有内容为详细设计草案；未导入、未启用，引用的逻辑能力不是已注册 API。

## 已确认的需求

- 用户视角优先；账单管理、还款支持、联系协商为核心，产品匹配只有明确融资/比较意图才进入。
- 所有需要用户选择或确认的步骤使用 `get_user_choice`，等待真实回传；用户已有明确且仍有效的指令不重复索取。
- 内部授权数据优先查询，缺什么补什么；材料先形成候选事实，关键冲突和修改核验后才保存。
- 工具提供事实、确定性计算和实际执行；Skill 定义工作方法，不产生权限、存储或自动任务。
- 主 Agent 按需加载 Skill 并恢复原任务，没有自动嵌套调用栈；共享流程不重复收集已有数据。

## 定义和工程约定（拟议）

可信服务上下文包含 principal_scope、session_id、task_id、run_id；用户资源范围由后端注入，不能让模型自行指定任意 user_id。Skill 输入表未逐行重复这些字段。

金额以十进制字符串及 currency 表达，未知为 null/unknown，不能用 0 代未知；不跨币种直接合计。日期/时刻分别编码，保留原始值、适用日期与 as_of。

内部拟议统一交接字段：schema_version、skill_name、task_id、status、result_type、data、missing_fields、conflicts、evidence、as_of、next_step。schema_version 初拟 1.0；服务必须校验，不要求模型始终严格生成此 JSON，也不假设原生 SkillToolset 自动具备此包装。

状态为 completed / partial / waiting_user / blocked / cancelled。blocked 在这里是业务任务状态。等待必须关联真实 request / function-call / invocation，保持用户、任务、会话与答案版本一致；超时、取消、重复回传由服务处理。查询和动作状态分开，partial 不表示保存或提交成功。

每项证据按可获得信息包含 source_ref、source_type、原文位置、effective_at、captured_at、verification_state；解析器没有置信度或位置时不得杜撰。用户自述、抽取、确认与机构回执各自保留。

## 规则填写和使用方法

规则编号固定。全局 G01—G08 在本文件填写；各 Skill 的规则仅在对应 references/business-rules.md 填写，其他文档引用编号，不维护第二份答案。业务规则分为组织通用口径、机构/产品有效规则、当前用户的个案选择，不能相互替代。

你可以直接替换“你的规则”中的【待填写】，或在聊天里按规则 ID 回复。状态可改为 待补充 / 已填写待审 / 已确认 / 暂不适用。每项应说明适用范围、例外、信息来源与一正一反样例；不适用也请注明原因。已填写不自动等于已批准发布。

规则没有明确之前，按每项“未定时处理”限制受影响分支，其他不依赖该规则的查询仍可继续。用户确认个案数据不能补足一条组织未定义的业务规则。
